How it works

One ReAct loop: reason → act → observe → stop?, for at most five planner rounds and twelve model calls in total. Those are different numbers because the planner is not the only thing that calls a model: a synopsis read sends the Observer, so one round can cost two calls. The total is the one that bounds the bill, it is enforced in agent/loop.py rather than asked for in a prompt, and its last call is reserved for the planner so a request that runs out of budget still returns an answer. Every tool is on the table on every turn. The planner chooses which to call, with what arguments, how many at once, and when it has enough to answer. Two things cost money, and one of them is not the planner — each planner round is one call, and each film the Verifier checks is another. Three of the five tools are free; build_shortlist spends one embedding per condition, about two millionths of a dollar each, and verify_candidates spends a text call per film it reads. A typical request is three planner rounds and three or four verifications.

The answer is gated on evidence, not on the model’s confidence. Two checks stand between the final message and the reply: it may not name more films than the ceiling, and it may not name a film that verification did not accept. Both are checked in agent/loop.py rather than asked for in the prompt, and each costs one correction turn. The second is what makes a shortcut pointless — skipping verification produces films with no verdicts, and no answer can be built out of them.

The cheapest-first ordering is a preference, not a path. Nothing in agent/loop.py sequences the tools; the order is policy, argued for in the system prompt, and the planner departs from it whenever a request calls for something else. When it does follow the order, each call hands the next a smaller candidate set, so the token-heavy tool only ever sees what survived the free ones. A question answerable by filtering alone costs two model turns and never touches the other three. The candidate set lives in Python between calls and never enters the prompt.

How it works

One bounded loop: the Planner reads the request, calls whatever tools it needs, and stops when it can answer. What it cannot do is answer with a film it did not check — the loop verifies that before replying.

The loop

Reason → Act → Observe → Stop? Every tool is on the table on every turn. The planner picks which to call and when it has enough; the loop ends on the turn that asks for no tool, and that turn is the answer. Nothing in the code sequences the tools.

Five tools — the planner calls these

ToolWhat it doesCost
CatalogFilter Columns: year, runtime, genre, studio, language, title exclusions. Exact and exhaustive. free
LexicalScreen Scans every plot for a word list the planner writes. The only thing that can answer an absence — you cannot search for something not happening. free
ShortlistFusion Searches each story condition separately, then merges the rankings. Films matching more conditions outrank films matching one of them better. 1 embedding per condition
SynopsisReader Plot text for named films, when there is one specific question about them. free
CandidateWalk Walks the shortlist best-first and sends each film to the Verifier. Returns accepted / rejected / unresolved. free

Two readers — a tool sends these, the planner cannot

ReaderShapeSent by
Observerone question × many filmsSynopsisReader
Verifierone film × every conditionCandidateWalk, once per film

The Verifier is what makes a film recommendable. It reads one film’s plot text with the whole list of requirements and returns yes / no / unclear per requirement, each with a sentence quoted verbatim from the text. A film is accepted only when every requirement says yes.

What the code enforces

Guardrails live in the data and the tool code, never in the prompt — a prompt is the wrong place for a rule that must not be forgotten, and one the model can read past is not a rule. Before any answer is returned, the loop checks it: it may not name more films than the ceiling, may not name a film verification did not accept, may not omit one it did, may not name films after a search without verifying them, and may not offer a follow-up the stateless API cannot honour. Each failure costs one correction turn.

Quotes are checked to be literal substrings of the source and discarded otherwise; a decisive verdict left without a quote is downgraded to unclear. The accepted list is assembled in Python, so the count an answer states is a count of a list rather than a claim the model makes about its own reasoning.

🧰 How this catalog was built

Three sources, prepared once offline and committed, so the repo runs from a fresh clone with no rebuild: a Disney/Pixar catalog from Kaggle (TMDB metadata), MPST plot synopses, and a Wikipedia cache scraped once. Nothing is fetched live — a live fetch would make a turn's latency depend on a third party.

The scope is Disney and Pixar feature films: 316 of them, 1937–2017. Two rules do the narrowing. Films are kept if a production company matches one of four studio names, and shorts are dropped at a 47-minute floor, because the studios release five-minute shorts that carry very high ratings on very few votes and would crowd out the features a recommendation query actually wants.

That studio list was wrong until recently, and it mattered more than anything else here. It named only the modern companies, and Disney was called Walt Disney Productions until 1986 — TMDB credits films by the name in use at the time. So the filter did not trim the catalog at its edges, it removed the canon: Cinderella, Peter Pan, Bambi, Dumbo, Pinocchio, Sleeping Beauty, Lady and the Tramp, 101 Dalmatians, Mary Poppins. Seventy-seven feature films. It stayed invisible because the remakes kept the titles under the modern name, so the catalog held Alice in Wonderland (2010) and Cinderella (2015) and looked complete. It was found by asking why a query about a flying human, animals and a clock never returned Peter Pan.

Plot text comes from whichever source has it: 198 films have an MPST synopsis, and the Wikipedia Plot section covers the rest, for 307 of 316 with readable story text. The remainder carry only a one-line overview, and the tools report those as insufficient_text rather than letting a film pass a check by having nothing to scan.

Ranking never uses the raw average. Each film carries a weighted_rating — the formula IMDb uses for its Top 250 — which pulls thinly-voted films toward the catalog mean until they earn enough votes to stand on their own.
