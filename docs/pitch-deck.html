Why · the tools we have all miss

So he asked the best tools we have.

🔎 IMDb search

Needs near-exact matches. Can't express “no deaths” or “involves animals.”

r/imdb: “Why is IMDb search so bad?”

📺 Netflix

Recommends at you, passively. You can't ask it a precise question.

Great engine — wrong flow.

✨ Gemini (Thinking)

Tries hard… then never knows when it's done.

“…there are actually several more titles” — after claiming “complete, exhaustive list.”

The one tool that should nail this — an LLM — can't guarantee it found them all.
Why · the query is four things at once

One sentence. Four different problems.

Structured

year ≥ 1990, studio = Disney

a database filter

Semantic

“involves animals”

meaning, not keywords

Judgment

“no on-screen death”

read the plot, decide

Exhaustive

every match, miss nothing

completeness

Fixed-K retrieval returns “top 5 similar.” It can never promise “all of them.”
How · the insight

Don't retrieve K guesses.
Bound the universe — then check every candidate.

Use the database to get the full set that matches the hard constraints. Then let the agent sweep it. Now “exhaustive” is a fact, not a hope.

How · pipeline vs agent

A pipeline runs steps. An agent makes decisions.

❌ Pipeline

Parse
→
SQL
→
Top-K
→
Answer

Same steps, same order — every query. K-limited. Can't promise “all.”

✅ Agent

Plan
→
Act
→
Observe
↻
Finish

Chooses tools per query. Loops until the goal is met. Self-corrects.

This is the difference the feedback asked for: the model decides the control flow at runtime.
What · the agent and its tools

The Controller decides. The tools do the work.

🤖

Controller

Reads what it knows so far.
Picks the next action.

structured_filter — full SQL match set
semantic_search — plot meaning (Pinecone)
inspect_movie — read one plot deeply
judge_predicate — subtle check, batched
ask_user — clarify if ambiguous
finish — goal met, answer
Which tool, how many times, and when to stop — all decided at runtime.
Watch it think

“Every 1990+ Disney movie, no deaths, with animals — be exhaustive.”

  • 1
    “Disney + ≥1990 are structured” → structured_filter → 80 films — the whole universe is now known.
  • 2
    “‘animals’ is about meaning” → semantic_search over those 80.
  • 3
    “‘no death’ needs judgment” → judge_predicate (batched, cheap).
  • 4
    Unsure about Ratatouille? → inspect_movie → re-judge. (self-correct)
  • 5
    All 80 classified → finish ✓ — an exhaustive list, and why each qualifies.
A “movies that feel like a warm hug” query would skip SQL entirely — the path changes with the question.

The one thing the feedback asked for

Why this is an agent, not a pipeline.

1 · Different question,
different trace

Tool choice happens at runtime. The steps log looks different for every prompt.

2 · Loops to a goal

Not a fixed number of steps — it iterates until every candidate is resolved.

3 · Self-corrects

Uncertain judgment → inspect deeper → re-decide.

Every /api/execute returns the full step trace — you can watch it decide.
